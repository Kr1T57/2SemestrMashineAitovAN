# 🏠 Прогнозирование стоимости недвижимости в Турции

Учебный проект по машинному обучению: сервис для предсказания цен на недвижимость (продажа и аренда) на основе характеристик объекта.

Включает предобработку данных, обучение моделей, валидацию на контрольных примерах и веб-приложение (FastAPI + Streamlit).

---

## 📌 В чём была проблема и как переделали решение

### 1. Старый подход (вместе с Рафаэлем — `СтырыйКонечныйКонец.ipynb`)
Сначала мы пытались обучить одну модель на всех данных (или просто выкидывали аренду, оставляя только продажу `listing_type == 1`).  
Сравнивали три алгоритма:
- Ridge (Линейная регрессия)
- HistGradientBoosting
- Random Forest

**Итог старого подхода:** Random Forest показал себя лучше остальных, но качество всё равно было низким — $R^2 \approx 0.35$, ошибка MAPE около $29\%$. 

### 2. Новый подход (`КонечныйКонец.ipynb`)
Главная ошибка была в смешивании или игнорировании специфики рынка. Продажа и аренда — это два абсолютно разных мира:
- **Продажа:** цены от сотен тысяч до десятков миллионов лир.
- **Аренда:** цены от 1 000 до 50 000 лир.

Если обучать всё в кучу или применять общие рамки, модель завышает аренду и ошибается в продажах. 

**Что изменили:**
1. **Разделили данные на два независимых пайплайна:** одна модель учится строго на продажах, вторая — строго на аренде.
2. Таргет логарифмируется (`np.log1p`), что убирает дикий перекос по ценам.
3. Добавили генерацию логичных признаков и сгруппировали редкие города/районы.
4. Проверили решение на контрольной выборке из 20 объектов (`test_real_estate_samples.csv`).

## 🛠️ Структура (Feature Engineering)

1. **Очистка данных:**
   - Перевод всех валют (USD, EUR, GBP) в единую валюту — `TRY`.
   - Парсинг комнат (например, `3+1` превращается в `4`).
   - Парсинг этажей (цоколи, подвалы приведены к 0, убраны отрицательные значения).
   - Обработка выбросов отдельно для аренды и продажи.

2. **Новые признаки:**
   - `size_per_room` — средняя площадь на одну комнату.
   - `floor_ratio` — отношение этажа квартиры к общей этажности дома.
   - `is_first_floor` / `is_top_floor` — флаги первого и последнего этажей.
   - Топ-города и районы оставлены как есть, редкие — схлопнуты в категорию `"Другой"`.

3. **Пайплайн (sklearn Pipeline):**
   - Пропуски в числах заполняются медианой (`SimpleImputer`).
   - Масштабирование чисел через `RobustScaler` (чтобы выбросы не ломали нормализацию).
   - Категории кодируются через `OneHotEncoder(handle_unknown='ignore')`.
   - Основная модель: `RandomForestRegressor(n_estimators=300, max_depth=30, random_state=42)`.

# 🎬 Сервис рекомендаций фильмов (Movie Recommendation System)

Учебный проект по машинному обучению: рекомендательная система полного цикла, сочетающая коллаборативные, контентные и ранжирующие алгоритмы. Включает собственную базу данных, REST API на FastAPI и интерактивный веб-интерфейс на Streamlit.

---

## 📌 О проекте и решаемых задачах

Основная цель проекта — разработать систему, способную решать проблему холодного старта, находить неочевидные связи между фильмами по оценкам аудитории и динамически подстраиваться под изменение вкусов пользователя.

### Архитектура решения:
1. **База данных (`cinema.db`, SQLite):**
   * Таблица `movies` (250 фильмов, полученных по API poiskkino.dev: названия, жанры, описания, постеры, рейтинги Кинопоиска).
   * Таблица `ratings` (более 7 100 оценок от 80 пользователей для построения матриц сходства).
2. **Бэкенд (`FastAPI`):** вычисление рекомендаций на лету, автоматическое обновление матрицы при выставлении новых оценок.
3. **Фронтенд (`Streamlit`):** адаптивный UI с постерами, карточками, каталогом и тестами разных видов фильтрации.

---

## 🧠 Реализованные алгоритмы рекомендаций

В системе реализовано 4 ключевых метода:

### 1. Взвешенный рейтинг IMDb (Bayesian Average) — «Топ-10»
Исключает проблему, когда фильм с одной оценкой 10.0 оказывается на первом месте:
$$w\_score = \frac{v \cdot R + m \cdot C}{v + m}$$
* $v$ — количество оценок у фильма;
* $R$ — средний балл фильма;
* $m$ — порог доверия (70-й перцентиль по количеству оценок);
* $C$ — глобальный средний рейтинг по всей базе.

### 2. Коллаборативная фильтрация (Item-based k-NN)
* Строится разреженная матрица `users × movies` (CSR-матрица).
* Сходство между фильмами рассчитывается с помощью **NearestNeighbors** с **косинусной метрикой** (`metric='cosine'`).
* Метод ищет фильмы, которые пользователи оценивали схожим образом.

### 3. Контентная фильтрация (Content-Based via TF-IDF)
* Поля `title`, `genres` и `description` объединяются в единый текстовый корпус.
* Векторизуются через `TfidfVectorizer(max_features=5000)`.
* Вычисляется матрица `cosine_similarity`. Метод рекомендует картины со схожим сюжетом, жанром и атмосферой даже без истории оценок.

### 4. Персональный гибридный пайплайн с решением «холодного старта»
* **Для нового пользователя (0 оценок):** выдается глобальный взвешенный Топ-10.
* **При малом числе оценок (1–3 оценки):** включается контентный поиск по любимому фильму.
* **При наличии истории оценок:** ищется $k$ похожих пользователей (User-based k-NN), а баллы непросмотренных фильмов взвешиваются пропорционально сходству соседей. При изменении оценок рекомендации мгновенно перестраиваются.
